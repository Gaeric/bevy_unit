* 项目目标
  实现基于 Bevy compute shader 的高性能 GPU 布料模拟，同时让项目所有者掌握其理论，
  能够解释、验证和修改实现。

  布料模拟是目的，XPBD 是当前的主要实现算法；本项目不以建设通用 XPBD 求解框架为目标。
  算法、数据结构和优化围绕布料的变形、碰撞及性能需求选择，不为了通用性扩展无关功能。

  GPU 求解是主线，不是完成 CPU 演示之后的可选优化。CPU 实现用于小规模参考和诊断；
  CPU/GPU 结果接近，不等于两者都正确，还需要能独立判断对错的小实验。

  Velvet 是算法和工程参考，不再要求逐项复刻。保留或改变其中的设计，都要说明它解决什么问题。
  放弃其特殊行为之前，要先讲清原理、修改方向，并用实验验证改善。

* 代码现在在哪里
  | 目录 | 用途 | 当前边界 |
  |------+------+----------|
  | =src/sim/= | CPU 求解、网格与约束生成、碰撞和空间哈希 | 已有实现与测试，不是独立正确性标准 |
  | =src/demo/= | 场景、面板、相机、抓取和 Mesh 写回 | 交互演示仍调用 CPU 求解器 |
  | =src/gpu/= | GPU 求解、动态邻居查找、诊断与 live 输出 | 默认 headless 对照和前批 live 视觉已有证据；新增配置/重置/计时待集成验证 |
  | =tests/= | CPU 与外围测试 | 测试存在或曾通过，不等于全部物理目标已验收 |

  =velvet-gpu= 是一次性无窗口对照；=velvet-gpu-live= 保留小型 fixture 实时入口。
  新 =velvet-gpu-scenes= 是共享场景的独立 GPU 入口，首批仅 1/2；CPU =velvet-scenes= 保留七场景。
  它们不是同一演示的 CPU/GPU 模式开关；当前 GPU 场景仍为线框，不含 CPU 材质、面板或抓取。
  生产求解与动态邻居生成都在 GPU；CPU 独立暴力查找只用于小规模诊断。
  动态邻居采用 counting hash、分层 scan、27 个真实 cell 查询、排序唯一 ID 与溢出统计。
  现有 gather 写法是“每个粒子收集自己的约束修正”，避免多个线程同时写同一粒子；
  它是当前实现，不是已证明最优的方案。

  与 Avian 的对象、算法用途和执行方式的区别见 [[file:plan.org::*与 Avian 的区别][计划中的比较说明]]。

  agent 要给出具体文件／函数、要检查的数据、正常关系，以及不同检查结果对应的下一步。

  用户主机 check/test 无错误，完整 60 步动态自碰撞对照、邻居专项及粒子碰撞专项已通过。
  用户于 2026-10-29 确认 GPU live 视觉表现符合预期；不据此推断暂停/单步专项、长时稳定性或性能。
  用户确认邻居遥测批次编译无问题；窗口数据、异步映射、异常告警仍待运行验证，不据编译成功宣称功能正常。
  用户当前无条件执行这些验证，授权保留待验证项并继续；静态碰撞器参照仍待集成验证。
  本批按用户同意合并推进启动配置、暂停重置和 GPU 分阶段异步计时；局部 CPU 测试通过，集成与设备运行待验证。
  CPU 参考不改，保留 Jacobi 路径；已验证批次不等于物理正确性或性能证明。数值与验证边界见 [[file:plan.org][当前计划]]。

* 运行现有程序
  从 workspace 根目录运行；先阅读根 [[file:../AGENTS.md][AGENTS.md]]。
  根 =Cargo.toml= 指向的 =../bevy_engines/bevy_0.20/= 必须存在，依赖也必须可解析。
  以下是已有入口，不代表本次已运行验收；交互演示需要显示环境，GPU 实验也需要可用图形设备。

  #+begin_src bash
    cargo run -j 2 -p bevy_cloth --example velvet-scenes         # CPU 七场景演示与面板
    cargo run -j 2 -p bevy_cloth --example velvet-gpu-scenes -- --scene 1 --paused
    cargo run -j 2 -p bevy_cloth --example velvet-gpu-scenes -- --scene collision --paused --timing
    cargo run -j 2 -p bevy_cloth --example velvet-gpu            # headless 60 步对照 + 邻居/粒子碰撞专项
    cargo run -j 2 -p bevy_cloth --example velvet-gpu-live       # 默认 16 分辨率、两层，运行中
    cargo run -j 2 -p bevy_cloth --example velvet-gpu-live -- --resolution 32 --layers 3 --substeps 4 --iterations 6 --paused --timing
    cargo run -j 2 -p bevy_cloth --example velvet-gpu-live -- --help
    cargo run -j 2 -p bevy_cloth --example velvet-00-sandbox      # 场景骨架，不是布料模拟验收
    cargo run -j 2 -p bevy_cloth --example velvet-01-collision    # 历史入口，当前实际加载 Attach 场景
  #+end_src

  只有 =velvet-scenes= 安装了完整交互插件：
  =1–7= 切场景 · =R= 重载 · =Space= 暂停 · =S= 单步 · =H= 隐藏参数列表 · =K= 画粒子 · =L= 线框。
  鼠标左键拖拽布料，中键转相机，滚轮缩放。UI 控件获得焦点时，Space 不切换暂停。
  操作与重载仍有已知限制，见下节；不要用入口名称代替检查实际场景。

  =velvet-gpu-scenes=：启动参数 =--scene 1|2|attach|collision=、=--paused=、=--timing=。
  =1/2= 切场景并暂停，=Space= 暂停/继续，暂停时 =S= 推进一 tick，=R= 重置并暂停，=C= 参照显隐；中键环绕、滚轮缩放。
  与 CPU 一样使用 60Hz；Attach 为1681粒子/四角挂点，Collision 为289粒子/顶部两角挂点。
  两端共用 =demo/scenes.rs::comparison_scene/scene_params/sweep_z_position=；GPU 不施加旧 fixture 扰动或弯曲柔度覆盖。
  球体按模拟 tick 更新，每 tick 上传当前与上一模型矩阵；首 tick 保留 CPU 初始历史仅平移的行为，不在本批改变语义。
  切换/重置清空待提交 tick、重建场景 Mesh/GPU buffers、复位动画时钟和采样；generation 拒绝旧 Mesh/读回。
  运动参照采用提取 tick 边界，与该次布料输出同步；仍只画碰撞器本体，不含 margin，不证明无穿透。
  CPU 既有 R/切换未完全复位状态的限制保留：严格对照初态请分别重启入口，CPU 场景2按2选择，勿以旧R当作已验证重置。

  =velvet-gpu-live=：=Space= 暂停/继续，暂停时 =S= 请求一个 fixed tick，=R= 重建同配置初态并暂停，=C= 隐藏/显示碰撞器参照。
  =R= 清空待提交 tick、重建 GPU buffers、复位计数/预热；日志 generation 区分实验，旧在途读回不混入新结果。
  它按 =FixedUpdate= 的 =Time<Fixed>= 排队每次 dt（默认 64Hz），就绪前不积压启动 tick。
  配置层数的彩色线框直接由 GPU 写 Mesh；无相机环绕或 CPU Mesh 读回。
  启动参数：=--resolution= 2..128（默认16），=--layers= 1..8（2），=--substeps= 1..16（2），
  =--iterations= 1..64（4），=--neighbors= 1..256（64），=--hash-interval= 1..64（3），
  =--no-self-collision=、=--paused=、=--timing=（默认自碰撞开、运行中、计时关）。
  代码接入可在 SolverLivePlugin 前插入 =LiveConfig=；仅启动生效，不能运行时改字段来调整已分配 Mesh/buffers。
  分辨率改变直径、总质量和速度上限，不是物理等价细化；允许范围也不保证设备容量/稳定性，超出 binding 限制会明确拒绝。
  静态碰撞器参照与求解共用 fixture 定义：地面有限网格、球体三个大圆、旋转盒体十二条边。
  参照只画本体，不含 collision_margin 或盒体圆角投影区域；不能据线框判定真实穿透深度。
  live 默认每累计64个已提交fixed tick异步读取16字节邻居统计并清零；大负载按最坏条目增量缩短窗口，最多一个请求在途。
  日志 =GPU cloth neighbor window= 中 =max_required= 是窗口峰值，=stored_entries= 是跨重建累计条目，
  =overflow_rows= 是溢出行事件数，=invalid_coordinates= 是无效坐标事件数；后二者非零会警告。
  这不是接触计数或 GPU 耗时；没有阻塞式等待，也没有粒子位置读回。

  CPU =velvet-scenes= 与 GPU 两个实时入口均显示应用 FPS（Bevy 实际帧间隔的平滑值），不是模拟tick频率或精确呈现帧数。
  CPU 面板 =CPU solve avg ... ms/tick (64 ticks)= 为64个实际完成tick的非重叠窗口均值，
  在 Solver::step 返回后立即计时，含子步和法线，不含误差诊断、碰撞器收集、Mesh写回或渲染。
  首窗口未满显示pending；切换/重载清空计时窗口，暂停保留最近均值，不因渲染帧数增加样本。
  GPU左上 =GPU solve avg= 读取异步timestamp的64个完成样本均值，旧窗口均值保留至下一窗口完成；
  显示off（需--timing）、unavailable/error、warmup或sampling进度及最近窗口skipped，重置/切换清空旧均值。
  CPU包含法线而GPU线框没有法线计算；GPU计时不含Mesh输出，两者不能直接相除作为端到端加速比。

  =--timing= 检查已启用的 TIMESTAMP_QUERY；不支持则只禁用计时，不强制申请功能或阻止求解。
  每代前 64 tick 预热，第65 tick 起采样；有 INSIDE_PASSES 时分邻居重建、粒子碰撞+apply、全部约束轮次，否则仅总耗时。
  求解日志单位 ms/tick；位置输出另记 ms/frame（所有层 pass 之和，暂停后也输出），不是整帧渲染耗时。
  每类满 64 个完成样本报告 avg/min/max、generation 和 skipped；最多三个计时样本在途，忙则跳过，不阻塞。
  每样本分配 query/读回资源，时间戳和采样会扰动工作负载；这不是预分配基准框架，也不测 CPU、排队、上传或读回耗时。
  不足窗口不汇总、无超时监控，计时错误会禁用计时；没有性能实测数据，不能据此宣称更快或达标。

* 已知限制与参考行为
  以下记录现状，不是要求永久保留的设计，也不是当前要同时修复的任务清单。

  - GPU/CPU 对照现在均保留四角零 rest 挂点和 LRA；预测仍对零逆质量粒子施加重力。
    挂点修正与拉伸、弯曲共享 Jacobi 计数，因此不是严格位置钳制，允许残余 pin drift，不能假称精确固定。
    日志含 CPU/GPU pin drift、LRA violation、步长、最大差及弯曲数量/柔度/初始角度误差；拒绝非有限数与长度不匹配。
    位置差 >1e-3 或速度差 >1e-2 时示例失败退出；这是诊断容差，不是物理正确性证明。
    bending 沿用 CPU 的退化保护和分母判断，与 CUDA 的保护细节有差异，见参考笔记；未加入累计 lambda 反馈。
  - CPU demo 切场景未清理旧抓取状态，释放时可能访问旧粒子索引；暂停期间松开鼠标也可能丢失释放事件。
    CPU demo 的 =R= 尚未复位所有状态，与本批 GPU live 重建初态不是同一路径。
  - 目前沿用了 disabled collider 的默认槽行为：不是彻底跳过，而是原点处半径为碰撞边距的小球。
    这是待评估的源行为，不以“1:1 复刻”作为正确性理由。
  - 场景 3 当前使用 8 个子步；布料立方体碰撞器的 =scale= 按 =2 × half_extent= 换算。
    这些是现有参数和尺寸口径，不是新的理论要求。纹理 V 朝向尚待视觉确认。
  - 本次没有运行 Velvet 可执行程序，也没有逐帧黄金数值对照。参考源码与现有 CPU 结果都不能替代独立验证。
  - SDF 保留源的预稳定/子步投影顺序及立方体圆角行为，不保证最终约束后完全不穿透。
    日志 max_sdf_correction 为最终位置的投影修正残差，不是真实穿透深度；运动历史已有主机模型测试，GPU 示例仅静态上传。
  - 主布料已启用动态自碰撞；容量 64 的已测批次峰值需求 27、无溢出或无效坐标。
    统计跨重建累计；初始有向接触数来自 CPU 输入诊断，不是 GPU 运行接触计数。固定候选表专项仍只作诊断。
  - live 使用 POSITION-only、12 字节 stride 的 LineList，无需法线、光照或阴影；粒子/Mesh 不读回，仅异步读取诊断统计。
    max-speed 仍为初始化时的上限，碰撞器变换静态；邻居遥测待设备验证，未测性能。
    不足配置阈值的尾窗口不单独采样；正常窗口为u32累计量预留4倍余量，但多tick帧/读回未完成会延长窗口，无超时告警，极端延迟仍可回绕。
    映射/poll 失败会警告并停止遥测，不停止求解；无日志不能视为没有异常。
  - GPU场景首批：局部合并提取harness23项通过；隔离manifest的库/全部example/测试目标 cargo check通过。
    使用临时原生库元数据stub，未链接或执行GPU；Attach/Collision视觉、切换/重置、动态碰撞仍待设备验证。
    后五场景未接入GPU；CPU既有重置/抓取缺口保留，不用两端都能启动来宣称对照通过。
  - 用户已验证 headless 批次及前批 live 视觉，遥测批次编译通过但运行待验证。
    前批 3 项几何测试、本批配置/CLI/队列/时间换算的局部 harness 通过，不能代替新增路径的 Bevy 集成、显示或设备验证。
    重建初态不承诺跨设备逐位确定性；配置增加负载不等于物理等价比较。
    agent 容器无 GPU，私有 target 的离线 Cargo 被 avian3d 解析阻塞；详见 [[file:plan.org::*验证记录与限制][验证记录]]。
