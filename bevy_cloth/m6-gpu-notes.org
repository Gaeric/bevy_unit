* 当前 GPU 原型（2026-10-28 源码检查，非运行验收）
  - =src/gpu/solver.wesl= 有四阶段：预测位置、求拉伸修正、应用修正、更新位置与速度。
  - =src/gpu/solver_gpu.rs= 建立粒子到拉伸约束的查询表，一次提交固定的 60 步，再读回位置和速度作 CPU 对照。
    它不是逐帧布料后端，未连接交互场景或渲染。
  - “每粒子收集修正”（gather）：一个线程查找该粒子的相关约束，只写自己的修正量。
    查询表采用 CSR，即连续数组加分段索引。求修正和应用修正分两次 dispatch（计算发射）执行。
  - 挂点、弯曲、SDF 碰撞、空间哈希、自碰撞和法线尚未进入这条 GPU 路径。
  - 当前对照的固定点与通过条件存在缺口，见 [[file:plan.org::*验证记录与限制][验证记录]]。
    本文不把数据布局相符或 CPU/GPU 接近当作算法已经正确的证据。

* 1. Velvet 的执行模型（参考事实）

  - **一 phase 一个 kernel**，全在默认 stream 顺序发射 → **kernel 边界即全局同步**
    （对应 bevy_cloth 侧"一 phase 一个 compute dispatch"）。
  - =Common.cuh=：=BLOCK_SIZE = 256=；=ComputeGridSize(n)= 取 =threads = min(n, 256)=、
    =blocks = ceil(n/threads)=；**一维**网格。
  - 参数走 **constant memory**：=__constant__ VtSimParams d_params=，每步 =SetSimulationParams()= 里
    =cudaMemcpyToSymbolAsync= 一次；**哈希另有一份独立的 =__constant__ HashParams d_params=**
    （=SpatialHashGPU.cu=，独立翻译单元）。
  - =substepTime= / =deltaTime= 是作为 **kernel 实参**逐个传的，不在 =VtSimParams= 里。
  - =Simulate()= 末尾一次 =cudaDeviceSynchronize()=，随后 =positions.sync()/normals.sync()=
    把结果拷回 GL VBO —— **渲染直接读求解器写的同一块内存**。

* 3. Velvet 的 GPU 工程点与本项目的选择边界

  1. **分散写入与原子累加（scatter / atomic）**：Velvet 让每条约束把修正写入相关粒子；
     多线程可能写同一位置，因此使用浮点 =atomicAdd=，避免累加结果丢失。
     当前 WGSL 拉伸原型不用浮点原子，改为每粒子收集自己的修正；其他阶段的实现尚未决定。
  2. =AtomicAdd(deltas, idx, val, reorder)=（.cu:13）轮换 x/y/z 的加法顺序以减少热点串行。
     这是源工程对原子累加的优化，不是当前 gather 路径的必做任务，也不是本项目已测性能结论。
  3. **法线**：源先清零，再按三角形原子累加，最后按顶点归一化。
     源的归一化缺少退化保护；不能因源如此就保留 NaN。按顶点收集相邻三角形是候选方案，尚未实现。
  4. =CollideParticles= 的 wrapper 内部还调用 =ApplyDeltas_Kernel=（.cu:384）。
     阅读调度时需注意这一步，不表示我们必须保留相同的函数组织。
  5. **空间哈希**：源先计算哈希，再用 cub 基数排序、查找桶区间、缓存邻居。
     邻居表为 =neighbors[id + n*slot]=，空槽标记为 =0xffffffff=。
     GPU 版尚未实现，排序或其他邻居查找方式留到对应问题再选，不预先规定 bitonic sort。
  6. **碰撞过滤**：源忽略初始距离 ≤ =particleDiameter²= 的粒子对，以避免相邻粒子不断互相排斥。
     这是启发式规则，不是通用物理定律；跨布料或初态接近时的漏碰撞风险需另行验证。

* 5. WGSL 实现需要另行判断的事情
  以下是查阅提示，不是现在要完成的任务清单。

  | 问题 | 当前做法或限制 | 尚需判断 |
  |------+----------------+----------|
  | 多线程写同一粒子 | 当前拉伸采用每粒子收集修正，不请求浮点原子扩展 | 其他阶段的并行方式必须结合正确性与测量选择 |
  | 分阶段执行 | 当前用独立 dispatch 分隔求修正与应用修正 | 不可用同一工作组内的屏障代替整个设备的阶段边界 |
  | 数据布局 | 当前将三维向量打包为四分量，统一参数放在 uniform 中 | 新数组与参数的对齐、读写权限和生命周期要独立核对 |
  | 邻居查找 | GPU 路径尚未实现 | 先解释要查哪些邻居及如何验证，再决定是否排序 |
  | 数组清空 | wgpu 的 =clear_buffer= 写零；源的空槽标记为全 1 | 若沿用非零标记，需另行填充；也可以在理解后改变表示 |
  | 资源绑定 | 当前粒子布局有 3 个 storage，约束布局有 7 个 | 扩展时核对实际设备 limits，不把旧表当作完整阶段均已验证 |
  | 渲染输出 | 当前只将位置和速度读回 CPU 作比较 | 读回再上传 Mesh 或渲染直接读 GPU 数组，尚未选择 |

  原子操作是保证并发读改写不丢结果的操作。标准 WGSL 的原子类型为整数；
  当前原型不依赖浮点原子扩展。这是现状，不预先替未来所有硬件和算法作决定。
