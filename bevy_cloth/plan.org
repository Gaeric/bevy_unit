* 目标与范围
  - [决定] 目标是基于 Bevy compute shader（在 GPU 上执行通用计算的着色器）的高性能布料模拟。
    XPBD（通过修正位置满足约束，并用柔度控制软硬程度的方法）是当前主要算法；不做通用 XPBD 框架。
  - [决定] CPU 求解器用于小规模参考与诊断，不是完成七个场景后才开始 GPU 的前置项目。
  - [决定] 用户掌握理论，能够解释、验证、修改代码，也是验收的一部分；代码能运行不等于完成。
  - [决定] Velvet 是参考实现，不再是必须逐项 1:1 照搬的规格。
    改变特殊行为前，先解释原理与原设计的问题，提出明确修改，再用实验验证是否改善。
  - 本文件只保留当前计划，旧迁移规格、里程碑与历史数值由 Git 保存，不折叠留档。

* 当前批次：SDF 碰撞（实现完成，设备运行待验）
  - [代码事实] 改动 =src/gpu/layout.rs=、=pipeline.rs=、=solver_gpu.rs=、=solver.wesl=；CPU/Velvet 不改。
    CPU/GPU 均保留 stretch、attach、bend，使用同一碰撞器表；自碰撞关闭。
  - [布局决定] SDF 独立布局为两个 uniform 和三个 storage（positions、predicted、colliders）。
    主 uniform 仍 48 字节，SdfParams 为 16 字节（数量、margin、friction、整步 dt）；
    collider 为 224 字节，显式 kind 编码，mat3 列补齐 16 字节，inverse/history mat4 按列打包。
    空表上传完整哑元素但 num_colliders=0；positions/predicted 为不同 buffer，不做重复别名绑定。
  - [算法事实] 每线程拥有一个粒子，按表顺序投影平面、球和旋转/非均匀缩放立方体，再计算摩擦。
    相对位移 =pred-position-velocity_at(pred)×h=；不按逆质量过滤，挂点也接受碰撞。
    沿用 CPU 的平面忽略旋转、球半径取 scale.x、立方体圆角和修正衰减，非通用精确 SDF。
    球心、圆角零长度、碰撞器 dt=0 沿用 CPU 保护；零切向位移显式返回零摩擦，避免除零。
  - [诊断输入] 保留 Z 鼓包及 bend_compliance=1e-4；增加静态平面 y=-2.15、球 (0,-1,0)/r=.35、
    旋转立方体中心 (.65,-1,.1)/scale=(.4,.6,.4)。球和立方体初态有接触，平面另有主机专项接触测试。
    GPU 批次仅验证静态上传；变换历史和运动摩擦有主机测试，未接实时动画/变换同步。
  - [调度事实] 每整步 stabilize_sdf（整步 dt，仅写 positions）；每子步 predict → collide_sdf（h，仅写 predicted）
    → [stretch → attachment → bending → apply]×iterations → finalize。预稳定不写速度，predict 刷新 predicted。
    约束共享计数和挂点残余漂移语义不变；不额外增加末尾碰撞投影来掩盖残差。
  - [时间决定] 插件 finish 时从主世界 =Time<Fixed>::timestep()= 取一次配置，传给初始化、CPU step
    和 GPU substep uniform；未覆盖 Bevy 默认值时为 1/64 秒。60 步、2 子步、4 轮仍一次批量提交，
    不是 FixedUpdate 实时推进；示例 schedule runner 的 60Hz 仅控制轮询节奏。运行中改 timestep 不会同步。

** 用户运行与共同定位
   #+begin_src bash
     cargo test -j 2 -p bevy_cloth --lib gpu:: -- --nocapture
     cargo run -j 2 -p bevy_cloth --example velvet-gpu
   #+end_src
   - [预期／待验证] 日志应包含 289 粒子、256 条 bend、3 个碰撞器、60 步、2 子步、4 轮、
     step_time=.015625、bend_compliance=1e-4、margin=.06、friction=.1、正初始角度误差。
     初始 SDF 最大修正应为正，initially_affected_particles>0；它们由 CPU 在输入上计算，不是 GPU 接触计数。
     =max_position_diff<=1e-3=、=max_velocity_diff<=1e-2= 才成功退出；非有限数据或长度不符直接拒绝。
     保持原容差；接触分支或 acos 导致差异时先定位，不自动放宽。它们不是物理正确性的验收标准。
   - 检查 =gpu/cpu_max_pin_drift= 和 =gpu/cpu_max_lra_violation=：前者为零 rest 到槽的距离，
     后者为活动正 rest 约束超 target 的最大值。非零不自动判错，先比较两边与迭代数关系。
   - 检查 =gpu/cpu_max_sdf_correction=：用同一 CPU 投影函数评估两边最终位置的最大修正量，
     不是真实穿透深度（尤其圆角 cube），也不要求为零；后续约束/finalize 可能再次带入碰撞体。
   - 若两边差异大：查 layout 的 kind、矩阵列和 224 字节 stride（mat3=48、inverse=96、history=160），
     再查 stabilize_sdf 是否每整步一次、是否取整步 dt；collide_sdf 是否在 predict 后且用 h。
     接着按单粒子/单碰撞器比较 sdf_correction → 投影后 pred → velocity_at → 切向摩擦，逐层定位。
     三类变形约束保持原 CSR；若仅残差大而 CPU/GPU 接近，先检查阶段顺序，不硬钳制挂点或加末尾投影。
     输入已加碰撞器，不要求 pin/LRA 指标等于此前 bending 日志。
   - 本批无 Mesh 输出。后续渲染必须 GPU-direct 写 Mesh，参考 Bevy =shader_advanced/compute_mesh.rs=；
     不增加 CPU Mesh 读回路径。现有批末位置/速度读回仅用于数值诊断。
   - 下一步先收集 SDF 运行日志、共同诊断本批，再决定邻居查找/粒子碰撞小批，不自动扩展。

* 与 Avian 的区别
  [源码核对，2026-10-28] workspace 的 =bevy_waltz= 使用 =avian3d 0.7.0=；
  相邻 =../avian/= checkout 是 =0.8.0-dev=，不能混用版本结论。以下以缓存中的 0.7.0 源码为依据。

  Avian 连接的是保持自身形状的刚体；本项目连接的是布料上的粒子，使整片布能够变形。
  共同点是可以通过位置修正满足约束，不同点是对象、约束和执行方式。

  | 比较项 | Avian 0.7.0 | 本项目目标／当前实现 |
  |--------+-------------+---------------------|
  | 对象 | 有位置、朝向、质量、转动惯量的刚体 | 以粒子和网格表示可变形布面 |
  | XPBD 用途 | 刚体关节与自定义约束；主要接触求解采用冲量方法，改变速度处理碰撞 | 以 XPBD 为主要方法处理布料变形，不做通用关节框架 |
  | 执行 | CPU；内置 XPBD 关节路径按顺序直接修正刚体 | GPU 主线；当前拉伸阶段同时读取本轮位置，各粒子收集修正，下一阶段统一应用 |
  | 所需能力 | 刚体运动、关节、碰撞及场景查询等 | 布料拉伸、弯曲、固定、物体碰撞与自碰撞，以及布面渲染更新 |

  - 用许多 Avian 刚体和关节可以做布料近似实验，但不会自动成为 GPU 布料模拟。
    GPU 组织方式的正确性和性能仍需验证；尚不能宣称本项目比 Avian 更快。
  - Avian 可作为约束数学的参考，日后也可能提供刚体环境；目前不安排适配，不承诺“一行接入”。
  - 公式不能只看名字：Avian 的 =compute_lagrange_update= 包含旧乘子项，但其距离关节传入 =0.0=；
    记录用于力回写的累计量，不等于在多次迭代中反馈旧乘子。到讨论柔度时再结合调用顺序展开。
  - 源码定位（相对 =avian3d-0.7.0= 源码目录）：
    =src/dynamics/solver/plugin.rs=、=xpbd/plugin.rs=、=xpbd/mod.rs::compute_lagrange_update=、
    =xpbd/joints/distance.rs=；后三者位于同一 =src/dynamics/solver/= 下。
