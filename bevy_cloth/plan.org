* 目标与范围
  - [决定] 目标是基于 Bevy compute shader（在 GPU 上执行通用计算的着色器）的高性能布料模拟。
    XPBD（通过修正位置满足约束，并用柔度控制软硬程度的方法）是当前主要算法；不做通用 XPBD 框架。
  - [决定] CPU 求解器用于小规模参考与诊断，不是完成七个场景后才开始 GPU 的前置项目。
  - [决定] 用户掌握理论，能够解释、验证、修改代码，也是验收的一部分；代码能运行不等于完成。
  - [决定] Velvet 是参考实现，不再是必须逐项 1:1 照搬的规格。
    改变特殊行为前，先解释原理与原设计的问题，提出明确修改，再用实验验证是否改善。
  - 本文件只保留当前计划，旧迁移规格、里程碑与历史数值由 Git 保存，不折叠留档。

* 协作方法与职责
  - [决定] 通过实际开发与共同排查问题熟悉项目，不采用先授课、再答题或通过知识考核才能推进的方式。
    CPU 求解器由用户编写，不默认用户需要重学其中的基本计算；实现时按需要查询公式和参考。
  - agent 推进一小批双方同意的框架代码，包括插件、资源、GPU 上传与读取、管线接线、渲染和诊断工具。
    求解公式等核心仍由用户实现；涉及算法数据布局、求解顺序或边界不明确的改动，先讨论，不包装成普通接线。
  - 用户运行、观察和验证，带回异常现象、日志或数据；双方共同定位，而不是 agent 直接猜原因并给出补丁。
    agent 具体说明文件和函数、该看哪些数据、正常值或应满足的关系，以及不同结果分别指向的下一项检查。
  - 每批改动交付：改了哪些文件、预期行为、运行方式、验证方法和已知限制。
    验证后再决定下一批；失败时先定位，不靠继续叠加功能绕过问题。
  - 理论解释服务于具体问题与方案判断，需要时用通俗语言、公式或数字说明，不安排脱离开发的必修练习。
    小测试和手算仍可作诊断工具，但不要求重复用户已掌握的内容。
  - 改代码前说明文件、区域、目的与范围，等待用户确认；每项逻辑改动单独给出可审阅替换。
    不顺手扩展任务，不未经确认替用户实现核心。
  - 记录时区分 [代码事实]、[手算预期]、[实验结果]、[决定]、[待验证]。
    未运行不记测试通过，未实测不记性能达标；不替用户宣称已经掌握，也不以答题作为验收。
  - 工作流遵守根 [[file:../AGENTS.md][AGENTS.md]]；测试必须带 =-j 2=，避免 Bevy 编译、链接耗尽内存。

** 先调查，再确定首批改动
   - 检查范围：=src/gpu/solver_gpu.rs= 的创建、执行和读回，=examples/velvet-gpu.rs= 的运行入口，
     以及 =src/demo/render.rs= 的 Mesh 更新。以上路径相对 =bevy_cloth/=。
   - 当前 GPU 一次计算 60 步后退出；要看到输出，需要确认数据怎样送到渲染，以及显示的是哪一步。
     不预先把一次性结果显示、逐步推进或逐帧读回视为已经选定的方案。
   - agent 给出首批改动的文件范围、预期画面或日志、运行命令、检查数据和已知限制，用户确认后再实现。
   - 当前固定点语义有缺口；方案必须明确使用什么初始状态、能验证什么，不能假称已有悬挂布料。
     若需要修改核心算法或求解顺序，另行讨论，不混入框架改动。
   - 不同时补齐弯曲、自碰撞、七个场景或进行大规模重构；读回用于验证不等于最终高性能路径。

** 验证与共同定位
   - 先确认 GPU 输出确实进入显示或诊断数据；仅看到静态布面，不能证明 GPU 已执行。
     明确显示数据的步骤编号、粒子数量，以及选定粒子的初值与输出，检查数值是否有限。
   - 出现问题时按数据流逐段检查：CPU 初值 → 上传的 GPU 数组 → 计算执行 → GPU 输出 → 渲染数据。
     实际排查时，agent 必须把每段落实到文件／函数、数据字段和预期关系，不只给抽象流程。
   - 例如“没有移动”，要区分计算未执行、输出未变化、结果未传到显示、相机看不到差异等情况；
     根据检查结果选择下一项，不直接把原因归到求解公式。
   - 记录运行条件、观察、定位证据和仍未确认的部分，再共同决定下一批工作。
     当前尚无这批改动的实现或运行结果，不标记完成。

  - [待验证] “高性能”需要硬件、粒子与约束规模、时间步、子步与迭代参数、误差和耗时证据。

* 与 Avian 的区别
  [源码核对，2026-10-28] workspace 的 =bevy_waltz= 使用 =avian3d 0.7.0=；
  相邻 =../avian/= checkout 是 =0.8.0-dev=，不能混用版本结论。以下以缓存中的 0.7.0 源码为依据。

  Avian 连接的是保持自身形状的刚体；本项目连接的是布料上的粒子，使整片布能够变形。
  共同点是可以通过位置修正满足约束，不同点是对象、约束和执行方式。

  | 比较项 | Avian 0.7.0 | 本项目目标／当前实现 |
  |--------+-------------+---------------------|
  | 对象 | 有位置、朝向、质量、转动惯量的刚体 | 以粒子和网格表示可变形布面 |
  | XPBD 用途 | 刚体关节与自定义约束；主要接触求解采用冲量方法，改变速度处理碰撞 | 以 XPBD 为主要方法处理布料变形，不做通用关节框架 |
  | 执行 | CPU；内置 XPBD 关节路径按顺序直接修正刚体 | GPU 主线；当前拉伸阶段同时读取本轮位置，各粒子收集修正，下一阶段统一应用 |
  | 所需能力 | 刚体运动、关节、碰撞及场景查询等 | 布料拉伸、弯曲、固定、物体碰撞与自碰撞，以及布面渲染更新 |

  - 用许多 Avian 刚体和关节可以做布料近似实验，但不会自动成为 GPU 布料模拟。
    GPU 组织方式的正确性和性能仍需验证；尚不能宣称本项目比 Avian 更快。
  - Avian 可作为约束数学的参考，日后也可能提供刚体环境；目前不安排适配，不承诺“一行接入”。
  - 公式不能只看名字：Avian 的 =compute_lagrange_update= 包含旧乘子项，但其距离关节传入 =0.0=；
    记录用于力回写的累计量，不等于在多次迭代中反馈旧乘子。到讨论柔度时再结合调用顺序展开。
  - 源码定位（相对 =avian3d-0.7.0= 源码目录）：
    =src/dynamics/solver/plugin.rs=、=xpbd/plugin.rs=、=xpbd/mod.rs::compute_lagrange_update=、
    =xpbd/joints/distance.rs=；后三者位于同一 =src/dynamics/solver/= 下。
