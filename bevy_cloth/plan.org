* 目标与范围
  - [决定] 目标是基于 Bevy compute shader（在 GPU 上执行通用计算的着色器）的高性能布料模拟。
    XPBD（通过修正位置满足约束，并用柔度控制软硬程度的方法）是当前主要算法；不做通用 XPBD 框架。
  - [决定] CPU 求解器用于小规模参考与诊断，不是完成七个场景后才开始 GPU 的前置项目。
  - [决定] 用户掌握理论，能够解释、验证、修改代码，也是验收的一部分；代码能运行不等于完成。
  - [决定] Velvet 是参考实现，不再是必须逐项 1:1 照搬的规格。
    改变特殊行为前，先解释原理与原设计的问题，提出明确修改，再用实验验证是否改善。
  - 本文件只保留当前计划，旧迁移规格、里程碑与历史数值由 Git 保存，不折叠留档。

** 保留：邻居遥测实现与运行待验证项
  - [前批事实] 私有统计 buffer/容量接口、异步采样和 3 项 StatsClock 测试已加入；用户仅确认编译通过。
  - [采样事实] 默认累计64个已提交tick后，在本帧tick提交后copy16字节统计 → clear诊断计数 → submit → map_async。
    本批大负载阈值按floor(u32::MAX / (4 × N × capacity × ceil(substeps/hash_interval)))限制在1..64，预留4倍余量。
    单个可复用 staging buffer，最多一个请求在途；以非阻塞 Poll 收取完成结果，暂停时仍收取已请求的结果。
    GPU-direct Mesh 输出不变，不读回粒子；headless 仍使用原有累计统计，不经过 live 清零路径。
  - [日志语义] =total_ticks/window_ticks= 是 CPU 提交计数，不是 GPU 完成时钟或耗时；=max_required= 是窗口需求峰值，
    =stored_entries= 跨窗口内重建累计，=overflow_rows/invalid_coordinates= 是事件数；后二者非零发出警告。
  - [限制] 不足配置阈值的尾窗口不单独采样；多tick帧/在途读回延迟时继续积累，没有超时监控，极端延迟仍可能回绕u32。
    poll/map 失败会警告并禁用遥测，不停止求解；无日志不能证明没有异常。
  - [已实现] GPU counting hash → 分层 scan → 桶散布 → 27 个真实 cell 查询；邻居 ID 排序去重，
    检查容量溢出与无效坐标。CPU 独立暴力模型仅用于诊断，生产路径不上传 CPU 邻居表。
  - [调度事实] 每整步 SDF 预稳定；每子步 predict → 按间隔重建邻居 → collide_particles → apply → SDF
    → [stretch → attachment → bending → apply]×iterations → finalize。保留 Jacobi，不切换图着色或累计乘子 XPBD。
  - [时间事实] live 在 =FixedUpdate= 按 =Time<Fixed>::timestep()= 排队每次 dt，默认 1/64 秒。
    shader/mesh 就绪前不积压启动 tick；就绪后保留请求，每个 dt 单独更新 uniform 并提交，避免多步共用最后一次 uniform 值。
    =Space= 暂停/继续，暂停时 =S= 请求一个 fixed tick；不是每显示帧强推一步。
  - [渲染事实] 配置层数的彩色 =LineList=，仅 POSITION，stride=12；compute 在 =camera_driver= 前直接写 Mesh。
    使用 =NoFrustumCulling=；每帧重新获取实际分配范围并检查布局/字节边界，避免旧 AABB 或 allocator 迁移失配。
    主路径无 CPU Mesh 读回、法线、光照或阴影；无相机环绕，有独立静态碰撞器参照及本批R重置。
  - [边界] headless 仍保留全部专项、CPU 参考及一次性 60 步批量对照；不把粒子对照读回接入 live。
    live max-speed 仍为初始化上限，碰撞器变换静态；邻居遥测运行尚待验证，未作性能结论。

* 与 Avian 的区别
  [源码核对，2026-10-28] workspace 的 =bevy_waltz= 使用 =avian3d 0.7.0=；
  相邻 =../avian/= checkout 是 =0.8.0-dev=，不能混用版本结论。以下以缓存中的 0.7.0 源码为依据。

  Avian 连接的是保持自身形状的刚体；本项目连接的是布料上的粒子，使整片布能够变形。
  共同点是可以通过位置修正满足约束，不同点是对象、约束和执行方式。

  | 比较项 | Avian 0.7.0 | 本项目目标／当前实现 |
  |--------+-------------+---------------------|
  | 对象 | 有位置、朝向、质量、转动惯量的刚体 | 以粒子和网格表示可变形布面 |
  | XPBD 用途 | 刚体关节与自定义约束；主要接触求解采用冲量方法，改变速度处理碰撞 | 以 XPBD 为主要方法处理布料变形，不做通用关节框架 |
  | 执行 | CPU；内置 XPBD 关节路径按顺序直接修正刚体 | GPU 主线；当前拉伸阶段同时读取本轮位置，各粒子收集修正，下一阶段统一应用 |
  | 所需能力 | 刚体运动、关节、碰撞及场景查询等 | 布料拉伸、弯曲、固定、物体碰撞与自碰撞，以及布面渲染更新 |

  - 用许多 Avian 刚体和关节可以做布料近似实验，但不会自动成为 GPU 布料模拟。
    GPU 组织方式的正确性和性能仍需验证；尚不能宣称本项目比 Avian 更快。
  - Avian 可作为约束数学的参考，日后也可能提供刚体环境；目前不安排适配，不承诺“一行接入”。
  - 公式不能只看名字：Avian 的 =compute_lagrange_update= 包含旧乘子项，但其距离关节传入 =0.0=；
    记录用于力回写的累计量，不等于在多次迭代中反馈旧乘子。到讨论柔度时再结合调用顺序展开。
  - 源码定位（相对 =avian3d-0.7.0= 源码目录）：
    =src/dynamics/solver/plugin.rs=、=xpbd/plugin.rs=、=xpbd/mod.rs::compute_lagrange_update=、
    =xpbd/joints/distance.rs=；后三者位于同一 =src/dynamics/solver/= 下。
